General Syntax
Use indentation like Python. Tabs only are allowed for indentation.
There is no concept of users defining types like in plain Python or JavaScript.
Use strict snake_case for variables, function names, parameters, and other ordinary identifiers.
Use PascalCase for element names and types.
Use # for comments. Comments may appear on their own line or inline after code.
Parentheses () can be used to indicate expression priority.
Do not use - for anything other than subtraction and negation. Use _ instead.

Types

Number
Can hold any type of number supported by JavaScript / TypeScript, except for NaN, ±Infinity

Boolean
use 'not' to negate Booleans
use 'equals' for ==
use 'less_than' for <
use 'greater_than' for >
use 'and' for &&
use 'or' for ||
use parentheses () to indicate priority

Color
Use Color(#123456) to define a custom color.

Element
Represents an element in the game. See Classes below.

Null
null represents a lack of something.
All values are truthy except false and null.

Type
Type holds one of the language's types.
Use is to check whether a value is a particular type.

Variable Assignment
Use:
let <variable> be <value> for variable assignments. Variable assignments can only occur inside functions.
e.g. let speed be 10
Variables use strict snake_case.

Classes/Elements

Use element to define a class representing a concrete element.
Use template_element to define an abstract element class.
Use has x to define class members.
Use has x with y to provide an initial value. This is only allowed for element definitions; such members will always have a value.
Use . notation to access members.
Functions automatically call their parent's implementation.
Only single inheritance is allowed, but nested inheritance is allowed


Functions
Functions can only be added to elements. There are no top-level functions.

Define a function using:
has function <function_name> needs <arg_name> <arg_name> ...:
  ...
  give <return_value>

Call functions using:
function_name(arg, arg, ...)

Functions can return a value using give
Arguments may optionally have a type.

Variable and Argument Types

Variables and arguments can have the following types:
Boolean
Color
Null
Number
Element
ElementType
An element's type can be obtained using .type.

Example:
let x be f.type 
if x is Fire: 
  do_something()
where Fire is an ElementType referring to the Fire element

Conditionals:
Use the following syntax:
if <condition>:
	...

else if <condition>:
	...

else:
	...

Loops
Collection Loop
use 'for_every x in <collection_name>' to iterate through a collection
e.g. for_every apple in apples

Range Loop
use 'go_through <start> to <end> with <variable>' to iterate through a range of numbers
e.g. 'go_through 1 to 10 with i'
This is similar to 'for (int i = 1; i <= 10; i++)'

Other keywords
use 'do_nothing' acts similarly to Python's pass.
use 'skip_iteration' acts similarly to continue.
use 'stop_looping' acts similarly to break.

Built-in functions
get_all_elements(): returns array of all elements in the game
convert_to(Element): converts the given element into another element type
spread_element(): adds the given element to all four adjacent sides.
disappear(): removes the given element from the grid
get_element_at(x, y): returns the element at (x, y), or null if the cell is empty or outside the grid
# Added in the 2026-11 polish pass
random(low, high): returns a whole number from low to high, inclusive
chance(percent): returns true roughly percent% of the time
place_element(ElementType, x, y): spawns a new element at (x, y) if that cell is empty and inside the grid; returns it, or null
is_empty(x, y): true when (x, y) is inside the grid and unoccupied
swap_with(other): swaps this element's position with another element
grid_width(), grid_height(): the grid size (128 x 128 in the app)
`x is Family` is true for elements that inherit from Family through "is like"


Examples

# In the actual language, Element would already be implemented 
# by the language and cannot be altered.

template_element Element:
  has position_x with 0
  has position_y with 0
  has color

	has function tick

	has function is_there_something_below:
		let below be get_element_at(position_x - 1, position_y - 1)
		let nothing_below be below equals null
		give not nothing_below

template_element Solid is like Element:
  has function tick:
  fall()

	has function fall:
		let something_is_below be is_there_something_below()

		if not something_is_below:
			let position_y be position_y - 1

template_element Liquid is like Element:
  has function tick:
    flow()
    
  has function flow needs element
    # do something with element that makes it flow properly with other liquids here
    do_nothing

template_element Gas is like Element:
  has function tick:
    do_nothing

template_element Energy is like Element:
  has intensity with 10

  has function tick:
    if intensity greater_than 0:
      let intensity be intensity - 1
    else:
      disappear()

element Water is like Liquid:
	has color with Color(#123456)

element Lava is like Liquid:
	has color with Color(#123456)

element Stone is like Solid:
	has color with Color(#123456)

element Ice is like Solid:
	has color with Color(#123456)
	has health with 50
	has melting_speed with 2

element Fire is like Energy:
	has color with Color(#123456)

interaction TNT t with Fire f:
  t.convert_to(Fire)
  let new_fire = t
  go_through 1 to 50 with i: 
    new_fire.spread_element()

interaction Ice i with Fire f:
	let i.health be i.health - i.melting_speed
	if health equals 0:
		i.convert_to(Water)


Naming Conventions
Variables = strict snake_case
Function names = strict snake_case
Parameters = strict snake_case
Element names = PascalCase
Built-in types = PascalCase
